# Asendus — substitution finder design

Date: 2026-10-14
Status: approved in brainstorming, pending written review

## Problem

Aili (school staff, Deutsches Gymnasium Kadriorg) arranges substitutions every morning when teachers are absent. Today she flips through the teachers' timetable PDF to find who is free in a given period, then fills a Word table (Kuupäev, Puuduva õpetaja nimi, Klass, Mitmes tund, Tunni asendaja nimi, Õppeaine). Finding eligible teachers by hand is slow and error-prone.

## Goals

- Upload the timetable PDF she already has; no conversion.
- Mark absent teachers for a date, see their lessons, get eligible substitutes per lesson.
- Record the substitutions and produce the day's table in her Word format (copy/print).
- Google sign-in, restricted to an email allowlist. Public landing page.
- Estonian UI.

## Non-goals (for now)

Duty rota (korrapidamine), multiple schools, notifying teachers, editing the timetable by hand, fairness statistics beyond "substitutions today".

## Users and access

- Single school, shared data for everyone allowed in.
- Allowlist via `ALLOWED_EMAILS` env var (comma-separated). Initial: `aili@alber.ee`, `tomimarkus@alber.ee`.
- Google sign-in exchanged for the API's JWT (same as `impulse`). Non-allowlisted email → `403 { "error": "..." }` from `POST /auth/google`.
- `/` is public. Every other route requires login; logged-in users visiting `/` are redirected to Täna.

## Architecture

Monorepo:

- `api/` — generated by `spring-boot-api-starter` (Spring Boot 4, Java 25, Maven, Postgres, Flyway, JWT, `dev` profile, Docker, GitHub Actions). App name `asendus`, package `com.asendus.api`, domain `api.asendus.alber.ee`.
- `web/` — Vite + React + TypeScript SPA. Google button via `@react-oauth/google` (ID token → `POST /api/v1/auth/google`). JWT kept in `localStorage`, sent as `Authorization: Bearer`. Hosted on Cloudflare Pages at `asendus.alber.ee` (same as gatherr's frontend).

## Timetable import

Source: the aSc Tunniplaan "õpetajad" PDF export, one page per teacher. Every page has the same layout: the title is `Õpetaja <Perekonnanimi> <Eesnimi>`; there are 7 period columns with times (1 = 8:45–9:30 … 7 = 14:15–15:00) and 5 day rows (Es, Te, Ko, Ne, Re). Each cell has the subject code at top-left (Ek, Ma, Ink, KKp, Digikirjaoskus…), the room at top-right, the class(es) in large text, and an optional group or note in small text at the bottom.

Parsing (PDFBox `PDFTextStripper` with text positions):

1. Read the title → teacher name (stored as shown, e.g. "Pärnpuu Taimi"; displayed as "Taimi Pärnpuu").
2. Locate the column header numbers 1–7 and the day labels Es–Re → x-boundaries of the columns and y-boundaries of the rows.
3. Group the remaining text into cells by x/y. Classify the text by font size and position: large → classes, small top-left → subject, small top-right → room, small bottom → group/note.
4. **Double lesson**: a cell whose vertical borders sit on non-adjacent column boundaries (e.g. Pupart 5R, Te 1–2; its text is centered between columns). It becomes one lesson per covered period. The text-position heuristic is tried first; the parsing spike decides whether the cell borders (line/rectangle paths via PDFBox `PDFGraphicsStreamEngine`) are also needed.
5. **Split cell**: two separate vertical clusters of large class text inside one slot, usually with a horizontal line between them (e.g. Ambos, Ne 5). It becomes two lessons in the same period.
6. Class strings like `2.3/2.4/2.5V` are kept as a raw string plus a split list.
7. Anything that can't be placed → a warning with the page number; the upload doesn't fail.
8. A file that doesn't look like an aSc teacher PDF (no grid headers found on any page) → 400.

**Teacher key**: the normalized name (Unicode NFC, trimmed, whitespace collapsed, lowercased) identifies a teacher across versions and in every API path. If a duplicate key appears within one PDF, the second one gets a ` (2)` suffix and a warning.

Placeholder teachers (e.g. "Puutöö", "Ingise keel Inglise keel", empty pages) are imported like real teachers. A placeholder flag (stored in `placeholder_flag` by teacher key, so it survives new versions) excludes them from candidate lists but still lets them be marked absent.

Versioning: each upload creates an inactive `timetable_version`. The preview shows teacher and lesson counts, added and removed teachers, and warnings. Activating it makes it the only active version. Uploading a new PDF deletes any earlier version that was never activated. Substitutions store copies of the names and classes, so old records survive changes to the timetable.

The first implementation task is a parsing spike: dump the text positions, font sizes and paths from all three sample PDFs in `~/Downloads` (`Tunniplaan_õpetajad.pdf`, `Tunniplaan_õpetajad-1.pdf`, `Tunniplaan 03.-04.09 õpetajad.pdf`), confirm the classification rules above, and adjust the rules if needed.

Tests use these sample PDFs, copied into `api/src/test/resources`.

## Eligibility rules

A teacher's working span for a weekday is from their first lesson to their last lesson **in the timetable**. Substitutions they have already taken do not extend it. For target period `p` on that weekday:

- `HIDDEN` if: the teacher has no lessons that day; or has a lesson in `p`; or is already assigned as a substitute in `p` that date; or is themselves absent in `p` that date; or is a placeholder.
- `FREE` if `first < p < last` (a gap in the middle of the day), or `p == last + 1`.
- `ASK_FIRST` if `p == first - 1` (this needs confirming with the teacher).
- `HIDDEN` otherwise (two or more periods outside the span).

Candidate lists are sorted FREE before ASK_FIRST, then by `todayCount` (fewest first), then by name. `todayCount` is the number of distinct periods that date in which the teacher is assigned as a substitute. Each candidate shows the subject codes they teach.

## Substitution flow (Täna)

1. Pick a date (default today); the weekday comes from the date. Weekends show a notice, and the API rejects absences on weekend dates with 400.
2. "Lisa puuduja" → choose a teacher (including placeholders) and optionally a period range (default: whole day, 1–7; for example "tuleb 3. tunniks" = 1–2) → the API creates an `absence` and returns one substitution row per lesson of that teacher in the range (period, classes, subject), empty by default. A split cell gives two rows for the same period. The rows are a **snapshot**: activating a new timetable later does not change them.
3. Each row: "Vali asendaja" opens the candidates for that period. She can pick one or more teachers and/or a free-text outcome (quick buttons: Koju, Tulevad hiljem, Klass kokku, Iseseisev töö, or her own text). Every change is saved immediately.
4. Removing an absence deletes its rows (with a confirm step in the UI).
5. "Asenduste tabel" shows the day's table: Kuupäev (d.mm), Puuduva õpetaja nimi, Klass, Mitmes tund, Tunni asendaja nimi (names joined with " / "; if free text is also set, it is appended after another " / "), Õppeaine. Sorted by absent teacher, then period. Buttons:
   - **Kopeeri** writes both `text/html` and `text/plain` to the clipboard, so it pastes as a real table into Word or OneDrive.
   - **Prindi** prints it with a print stylesheet.

The table is built client-side from `GET /days/{date}`. The subject column maps timetable codes to full names using a static map in the frontend, seeded with every code found in the sample PDFs (Ek → eesti keel, Ink → inglise keel, Ma → matemaatika…). Unknown codes are shown as they are.

## Data model (Flyway V2+)

- `timetable_version(id, uploaded_at, uploaded_by, file_name, active, warnings text[])`
- `teacher(id, version_id, key, name)`
- `lesson(id, teacher_id, weekday 1–5, period 1–7, classes text, subject text, room text, note text)`
- `absence(id, date, teacher_key, teacher_name, from_period, to_period, created_by)`; unique on `(date, teacher_key)`.
- `substitution(id, absence_id, period, classes, subject, substitute_keys text[], substitute_names text, free_text)`
- `placeholder_flag(teacher_key)` keeps the placeholder flags across versions.

## API (all under `/api/v1`, JWT required except auth/health)

- `POST /auth/google`, `GET /me` (from the starter, plus the allowlist)
- `POST /timetables` (multipart) → preview; `POST /timetables/{id}/activate`; `GET /timetables/active`; `GET /timetables/active/teachers/{key}` (grid); `PUT /teachers/{key}/placeholder`
- `GET /days/{date}` → absences with their rows; `POST /days/{date}/absences {teacherKey, fromPeriod?, toPeriod?}`; `DELETE /absences/{id}`
- `GET /days/{date}/candidates?period=p` → `[{key, name, status, subjects, todayCount}]`
- `PUT /substitutions/{id} {substituteKeys, freeText}`
- `GET /days` → dates that have at least one absence (Ajalugu)

## Frontend pages

- **Avaleht** `/`: what the app does, plus the "Logi sisse Google'iga" button.
- **Täna** `/paev/:date`: the flow above.
- **Tunniplaan** `/tunniplaan`: upload, preview and activate; teacher list with placeholder toggles; a read-only grid per teacher.
- **Ajalugu** `/ajalugu`: list of dates linking to `/paev/:date`.

Mobile-friendly: she uses her phone (the screenshot was from a phone).

## Error handling

- API errors are always `{ "error": "..." }`; the frontend shows Estonian toasts.
- 401 → clear the token and go to `/`. 403 from the allowlist → "Sul pole ligipääsu, küsi Tomilt".
- Parser warnings are shown in the preview and don't block activation.
- No active timetable → Täna shows "Lae esmalt tunniplaan üles" with a link.
